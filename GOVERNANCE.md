# Vexa Governance Model

This document outlines the governance model for the Vexa project.

## 1. Project Philosophy

Vexa is an open-source security platform dedicated to privacy-first, air-gapped security analysis. Our goal is to provide enterprise-grade security tools that respect developer privacy.

## 2. Decision Making Model

Vexa currently follows the **Benevolent Dictator for Life (BDFL)** model, which is common for early-stage open-source projects.

* **Noviq Technologies** acts as the primary maintainer and decision-maker.
* Core maintainers have the final say on all architectural decisions, feature inclusions, and pull request approvals.
* We prioritize community feedback and aim for consensus, but the core maintainers reserve the right to make the final call to ensure the project's long-term health and security.

## 3. Roles

### Users
Users are community members who use Vexa. We encourage users to participate by:
* Reporting bugs.
* Requesting features.
* Participating in GitHub Discussions.

### Contributors
Contributors are community members who submit code or documentation. All contributors must follow the [CONTRIBUTING.md](CONTRIBUTING.md) guidelines.

### Maintainers
Maintainers are individuals with write access to the repository. They are responsible for:
* Reviewing and merging pull requests.
* Managing the roadmap and issue tracker.
* Ensuring the security and stability of the project.

## 4. Communication Channels

* **Issues**: Technical bugs and feature requests.
* **Discussions**: General questions, ideas, and roadmap feedback.
* **Email**: Security-sensitive issues should be sent to security@noviqtechnologies.com.

## 5. Changing the Model

As the project grows, we may transition to a more distributed governance model (e.g., a Steering Committee). Any such change will be proposed and discussed in the public Discussions forum.
